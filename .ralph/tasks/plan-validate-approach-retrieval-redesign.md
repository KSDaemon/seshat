# `validate_approach` — Retrieval, Not Verdict — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Strip the deterministic judgment layer (`verdict` / `ready` / `must_fix` / `what_would_help`) from the `validate_approach` MCP tool so it returns only retrieval — relevant graph records plus neutral counts — and rewrite its guidance so the agent judges applicability itself.

**Architecture:** `validate_approach` lives in `seshat-graph` (engine: `validate_approach.rs`) and is exposed via a thin handler in `seshat-mcp` (`tools/validate_approach.rs`), described in `server.rs`, logged by `call_logger.rs`, and prompted via `skills/seshat/SKILL.md` + `rules/seshat.md`. We remove the judgment fields/functions from the engine, rename `rules`→`relevant_rules` (`RuleViolation`→`RelevantRule`, drop `severity`, add `description_hash`), make `summary` a neutral count string with an explicit empty-case message, replace verdict-branched `next_steps` with one static procedural list, switch telemetry to section counts, and de-verdict all prompting. The retrieval/ranking machinery (tokenization, stop-words, `MIN_RULE_RELEVANCE_TOKENS` gate, partitioning, caps) is untouched.

**Tech Stack:** Rust (workspace crates `seshat-graph`, `seshat-mcp`, `seshat-cli`), `rusqlite`, `serde`, `rmcp`, Markdown skill/rule files.

/// Convert pre-filtered rule conventions into `RelevantRule` structs.
fn relevant_rules_from_conventions(rule_convs: Vec<ConventionResult>) -> Vec<RelevantRule> {
    rule_convs
        .into_iter()
        .map(|c| {
            // Only attach evidence when there is a non-empty snippet.
            let evidence = c
                .examples
                .first()
                .map(|ex| CodeSnippet {
                    content: ex.snippet.content.clone(),
                    truncated: ex.snippet.truncated,
                })
                .filter(|snippet| !snippet.content.is_empty());

            RelevantRule {
                description: c.description,
                description_hash: c.description_hash,
                evidence,
            }
        })
        .collect()
}

/// Extracts section counts (`relevant_rule_count`, `convention_count`,
/// `decision_count`, `observation_count`, `duplicate_count`,
/// `contradiction_count`) from the serialized response data.
pub fn validate_approach_result(response_data: &serde_json::Value) -> serde_json::Value {
    fn count(response_data: &serde_json::Value, key: &str) -> usize {
        response_data
            .get(key)
            .and_then(|v| v.as_array())
            .map(|a| a.len())
            .unwrap_or_else(|| {
                tracing::debug!(
                    "validate_approach_result: key '{key}' missing or not an array"
                );
                0
            })
    }

    serde_json::json!({
        "relevant_rule_count": count(response_data, call_logger_keys::validate_approach::DATA_RELEVANT_RULES),
        "convention_count": count(response_data, call_logger_keys::validate_approach::DATA_CONVENTIONS),
        "decision_count": count(response_data, call_logger_keys::validate_approach::DATA_DECISIONS),
        "observation_count": count(response_data, call_logger_keys::validate_approach::DATA_OBSERVATIONS),
        "duplicate_count": count(response_data, call_logger_keys::validate_approach::DATA_DUPLICATES),
        "contradiction_count": count(response_data, call_logger_keys::validate_approach::DATA_CONTRADICTIONS),
    })
}
